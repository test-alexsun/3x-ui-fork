# Read-only baseline VPS hl

Дата: **29 октября 2026**. Основные успешные наблюдения: приблизительно **09:27–09:35 UTC / 15:27–15:35 Asia/Omsk**. Это снимок состояния на время диагностики, а не постоянный мониторинг.

## 1. Результат

В обследованных пакетах, процессах, systemd units, стандартных каталогах и listening sockets **не обнаружена установка 3x-ui, Xray, Nginx, Certbot, Docker, PostgreSQL или VPN-служб**. `x-ui.service` имеет `LoadState=not-found`. Сервер соответствует сценарию новой установки; мигрировать существующую панель на `hl` сейчас нечего.

Конфигурации VPS не менялись, службы не перезапускались, firewall не изменялся, файлы не удалялись, пакеты не устанавливались. Загруженные исходники исследовались локально. Никакие скрипты старого или официального installer на `hl` не выполнялись. Пароли, UUID, API tokens, DSN и private keys не извлекались и в отчёт не включены.

## 2. SSH и методика

Сначала выполнен `ssh -G hl`. В sandbox-контексте Windows alias не подхватил пользовательскую конфигурацию; повторная проверка в пользовательском контексте разрешила существующий alias:

| Параметр | Результат |
|---|---|
| Alias | `hl` |
| Remote host | `138.124.245.193` |
| User / port | `root` / TCP `22` |
| IdentityFile | Существующий `~/.ssh/id_ed25519_hl_vps`; содержимое не читалось |
| Known hosts | Существующий `C:\Users\Assa\.ssh\known_hosts` |
| Key authentication | Успешная неинтерактивная аутентификация с `BatchMode=yes` |
| Host key verification | `StrictHostKeyChecking=yes`; проверка не отключалась |
| Known hosts update | `UpdateHostKeys=no`; не запрашивалось принятие нового ключа |

Некоторые повторные подключения завершались timeout на SSH handshake. Изменение IPQoS не решило проблему. Вызов с **`KexAlgorithms=curve25519-sha256`** успешно выполнил финальный inventory. Это наблюдаемый workaround для конкретного вызова, **не доказанный диагноз причины timeout**. Пользовательский SSH config и серверный sshd_config не менялись. Точная причина требует отдельной диагностики при необходимости.

Параметры успешного подключения были эквивалентны:

```text
ssh -T -o BatchMode=yes -o StrictHostKeyChecking=yes -o UpdateHostKeys=no -o ConnectTimeout=15 -o KexAlgorithms=curve25519-sha256 hl
```

Диагностика читала `/etc/os-release`, `uname`, `lscpu`, `free`, `df`, `ip`, `/etc/resolv.conf`, `ss`, systemd metadata, package status, названия процессов, стандартные пути и ограниченную выборку journal. Ранняя передача multiline script из PowerShell имела CRLF/formatting-ошибки; финальный успешный проход нормализовал CRLF на входе shell и корректно прочитал версии пакетов. Невыполненный фрагмент не принимался за отрицательный результат.

SSH и сама ОС могут записывать входы/сессии в системный журнал. Под read-only здесь понимается отсутствие инициированных изменений настроек, данных приложений и состояний служб, а не побайтовая неизменность всех системных файлов при работающем сервере.

| Проверка | Результат | Интерпретация |
|---|---|---|
| nft package | `nftables 1.1.3-1`, установлен | Наличие инструмента, не наличие правил |
| `nft list ruleset` | Пустой вывод, exit 0 | На момент снимка nft ruleset пуст |
| nftables.service | Disabled / inactive | Служба не активна; это отдельно от состояния kernel rules |
| UFW / iptables tools | В проверенном PATH не обнаружены | Альтернативная локальная политика через эти утилиты не найдена |
| TCP IPv4/IPv6 :22 | sshd на wildcard | Единственный обнаруженный публично слушающий порт |
| TCP IPv4/IPv6 loopback :6010 | sshd-session | Локальный listener существующей SSH-сессии; вероятно X11 forwarding, не подтверждён как отдельный сервис |
| UDP listeners | Не обнаружены `ss -lntup` | На момент проверки UDP-сервисы не слушали |

TCP 80/443 и UDP 443 локально свободны в этом снимке, но **не проверены извне**. Правила cloud/provider firewall, security group и upstream ACL неизвестны. Пустой local nft ruleset не означает, что все порты доступны из Интернета. Внешнее сканирование и нагрузочная диагностика не проводились.

Listener :6010 не завершался и не перенастраивался. Будущий preflight обязан сохранить реальный SSH-доступ и существующие established-соединения. Старый подход с `ufw disable` или `fuser -k` здесь применять нельзя.

## 8. Вывод для будущей установки

Начальный сценарий — Debian 13 amd64/systemd, чистая установка с небольшим выбранным набором профилей. Причины переустанавливать ОС по результатам аудита нет. До будущего apply нужны выбранные домены, внешние DNS A/AAAA, ingress/провайдерский firewall, согласованный TLS-профиль, закреплённые panel/core artifacts, безопасный bootstrap credentials, reservation портов и проверенный механизм rollback.

SQLite разумен как начальный backend одиночной панели; PostgreSQL возможен, но не требуется фактическим состоянием `hl`. Решение о PostgreSQL следует принимать по требованиям эксплуатации, а не из-за наличия libsqlite3. Nginx и Certbot устанавливаются только при выбранной архитектуре TLS/сайта. AWG kernel и обязательный внешний converter не нужны для стандартной панели.
